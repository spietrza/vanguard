How it works

From card to pull request

Six stations, the same for every card. You set the trigger and you merge; Taskcell does the toil in between.

  1. Card

    Label an issue on GitHub, GitLab or Linear, or move a card on a GitHub Projects board. A card too vague to build goes back as needs info before any model runs.

  2. Spec

    A planner reads the code and writes a tech spec with acceptance criteria. It is posted on the issue, and you get a window to read it before the build starts.

  3. Sealed cell

    The agent builds the card in a Docker container of its own: non-root, no new privileges, a minimal capability set, no repository token, one git worktree per card.

  4. Gates

    Your verify script runs and the host scans the diff for secrets. A red gate sends the card back for a repair, at most twice; the second can run on a stronger model.

  5. Review

    A reviewer reads the diff in a fresh context and fixes what it finds. Give it a second model, for example Codex reviewing Claude's work.

  6. Pull request

    The host pushes the branch and opens the PR: ready for review when every gate passed, a draft when one did not. On GitHub, your review comments go back for a revision. You merge.

Swappable parts

Bring your tracker. Bring your model.

The source and the engine are plug-in parts on the line. Change either one with a flag; the cell, the gates and the review stay the same.

Security

The agent is treated as hostile

It reads text anyone can write: issues, repository files, dependencies. So it works inside a cell, and everything that can do damage stays outside.

The host

Your machine or server. Only it holds what can do damage.

  • The GitHub or GitLab token
  • The real model key, inside the LLM proxy
  • The secret scan of every diff
  • Dropping edits to CI config
  • Pushing the branch and opening the PR

The cell

One container per card.

  • Non-root, no new privileges, minimal capabilities
  • No repository token
  • A one-run nonce instead of your model key
  • Secrets in RAM, never in argv or on disk

Out of the cell

  • registry.npmjs.orgallowed
  • pypi.orgallowed
  • github.comallowed, no token
  • api.anthropic.comvia the proxy
  • anything elserefused

With the egress allowlist on. Without it, the cell's network is open.

  • A sealed cell per card

    A Docker container, non-root, with no-new-privileges and every capability dropped except the three it needs to own files (CHOWN, FOWNER, DAC_OVERRIDE). No GitHub or GitLab token inside. Secrets arrive as an in-RAM file, never in argv or docker inspect.

    On a Linear task the cell gets the Linear key, to read the issue.

  • The key stays out

    The LLM proxy, a sidecar on the host, holds the real model key. The agent gets a nonce that is useless after the run.

    CLI: --llm-proxy, for Claude, Codex on an API key, z.ai and OpenRouter. The Hub always uses it for those. Codex on a ChatGPT plan, Cursor and Meridian still put their key in the cell, and the Hub warns you.

  • An egress allowlist

    The cell sits on an internal Docker network whose only way out is a proxy that tunnels allowlisted hosts. A process that ignores the proxy settings has no route out.

    --egress, and implied by --llm-proxy.

  • A secret scan before every push

    The host scans the diff before anything leaves. A hit pushes nothing.

  • CI config never ships

    Agent edits to .github/workflows, .github/actions, .gitlab-ci.yml and .gitlab/ YAML are dropped on the way out of the cell, and the PR lists them under Not included.

  • A Hub that answers only to you

    It binds to 127.0.0.1 by default, rejects unknown Host headers against DNS rebinding and needs a token minted at each launch.

    It has no login yet: on a server, put it behind Tailscale or an authenticating proxy.

  • Only trusted comments steer it

    A comment counts as an instruction only when it comes from a repository member, the issue author or a login you list. Everyone else's text is ignored, and the CI watchers skip issues and PRs opened by outsiders.

    --feedback-authors adds logins. From 1.13.0.

  • Pinned images and tools

    The sandbox, runner and Hub images are pinned by digest, the bundled CLIs by exact version and the Cursor download by checksum. .dockerignore keeps .env files out of image layers.

    From 1.13.0.

  • Host git without repo hooks

    When the host commits and pushes the agent's work, git runs with the repository's hooks switched off, so a hook planted in the change cannot run on your machine.

    From 1.13.0.

No third-party audit yet. The boundaries are written down in the README, in a self-hosted security review and in a control-by-control mapping to the OWASP Top 10 for agentic and LLM applications. Found a hole? Report it privately; you get an answer within 7 days.

Self-host

Your machine. Your plan.

Taskcell runs where Node 24 and Docker run: a laptop, a home server, a VPS. It uses the AI subscription or API keys you already pay for.

Install from source

git clone https://github.com/spietrza/taskcell.git
cd taskcell
pnpm install && pnpm build
docker/build.sh       # the sandbox image
pnpm link --global    # puts vanguard on your PATH

Also needed: gh for GitHub, glab for GitLab or the linear CLI for Linear.

Why the command says vanguard Taskcell used to be called Vanguard. The CLI keeps its pre-rename name, vanguard, for now, and so do the VANGUARD_* variables, the vanguard:* labels and the .vanguard/ folder.

  • One card from the CLI

    Run a single issue end to end, with the key held by the LLM proxy.

    # token from: claude setup-token
export CLAUDE_CODE_OAUTH_TOKEN=…
vanguard run --github you/app#42 \
  --repo ../app --llm-proxy

    Or vanguard watch to keep picking up labelled issues on its own.

  • The Hub on your machine

    Projects, the task board with New Run, the fleet, and every run's record, in a browser.

    pnpm build:ui
vanguard hub --repo ../app
# http://127.0.0.1:7777

  • The Hub on a server

    A Docker image for a VPS or a home server, Coolify or plain Compose.

    docker build -f docker/hub.Dockerfile \
  -t vanguard-hub .

    Behind Tailscale or an authenticating proxy, never a published port. Mounting the Docker socket gives the Hub root on that host.

  • Desktop appThe Hub as a native app, starting with macOS.
  • Mobile appConnects to your own instance.
  • Managed hostingLater, for teams that want it run for them.

FAQ

Questions

What does it cost?

Taskcell is open source under the MIT license. You pay your model provider, through the plan or the API keys you already have. Each run records its tokens, cache use and cost, and a per-run budget cap stops a run that gets too expensive (on the engines that run the Claude CLI; not yet on Codex or Cursor).

Will it merge anything on its own?

No. It opens pull requests and a person merges them. A failed gate makes the PR a draft rather than hiding the failure.

Do I need a Claude subscription?

No. Claude Code runs on a Claude subscription token or an API key; Codex on an OpenAI key or a ChatGPT plan; Cursor, OpenRouter and z.ai on their own keys. A run that uses only Codex or Cursor needs no Anthropic credential.

Where does my code go?

Your repository is checked out on your host and the agent works on it inside the cell. What the agent sends to its model provider goes there, as with any coding agent. One opt-in feature, the difficulty probe, sends issue text to a decision-model endpoint; it is off unless you turn it on.

What happens when the tests fail?

The card goes back for a repair, at most twice. If it is still red, the PR opens as a draft with a verify-failed label, so you see the failure instead of a green-looking PR.

Why is the command called vanguard?

Taskcell used to be called Vanguard. The CLI, the VANGUARD_* variables, the vanguard:* labels and the .vanguard/ folder keep that name for now; the old repository URL redirects to the new one.

Can it run in CI instead of on my machine?

Yes. Reusable GitHub Actions workflows run the same factory when you label an issue, and the Hub can import those runs' records to show them.

Is it audited?

Not by a third party. The security model and its limits are documented in the repository, and vulnerabilities can be reported privately through GitHub.
