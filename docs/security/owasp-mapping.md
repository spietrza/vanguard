# OWASP mapping (self-assessment)

This page maps Taskcell's security controls to two OWASP lists:

- the [OWASP Top 10 for Agentic Applications 2026](https://genai.owasp.org/resource/owasp-top-10-for-agentic-applications-for-2026/) (ASI01 to ASI10, published December 2025);
- the [OWASP Top 10 for LLM Applications 2026](https://genai.owasp.org/resource/owasp-genai-llm-top-10-2026/) (LLM01 to LLM10, published 3 August 2026). The IDs and names below are taken from the official 2026 PDF. The 2026 edition reorders the 2025 list and has no System Prompt Leakage entry; LLM08 is now Hidden Context Exposure. Older material that cites 2025 IDs (for example LLM06 Excessive Agency) uses different numbers.

**This is a self-assessment, not a certification.** The maintainers wrote it from the source code and from internal security reviews. No third party has audited or attested it, and it does not cover how you deploy Taskcell. Settings such as `--egress`, `--llm-proxy`, repository Actions permissions and where the Hub listens change how much of each control applies to your setup.

Findings from internal security reviews are fixed on `main`, for example host git hardening, the Hub token handoff and Hub endpoint hardening, sandbox egress and LLM proxy filtering, comment-author trust on every task source, publish-time redaction, and pinned image dependencies. They ship in the next release (1.13.0). The latest tagged release, v1.12.0, does not include them. To report a problem, see [SECURITY.md](../../SECURITY.md). For how the boundaries fit together, see [boundaries.md](boundaries.md).

## Threat model in one paragraph

Taskcell treats the coding agent as hostile. Issue text, PR text, repository files and dependencies can all carry instructions, so the design assumes the agent may try to leak credentials, reach the network, or change what gets pushed. The agent runs in a Docker sandbox with no repository token. The host, not the agent, copies changes back, scans them, pushes the branch and opens the pull request, and a human reviews and merges it.

## OWASP Top 10 for Agentic Applications 2026

| ID | Risk | Taskcell controls | Notes |
|---|---|---|---|
| ASI01 | Agent Goal Hijack | Untrusted text is escaped before it goes into prompt tags ([`src/context/escape.ts`](../../src/context/escape.ts)). The PR reviewer is told that the PR title, body, diff and comments are untrusted ([`src/runners/pr-review.ts`](../../src/runners/pr-review.ts)). Comments count as instructions only from trusted authors ([`src/tasks/comment-trust.ts`](../../src/tasks/comment-trust.ts)). The GitHub Actions callers gate on the issue author and the sender ([`.github/workflows/vanguard-implement.yml`](../../.github/workflows/vanguard-implement.yml)). `review-pr`/`review-mr` read `CLAUDE.md`/`AGENTS.md`/skills from the repository's default branch, never the PR's own base branch, so a PR cannot steer the reviewer that gates its own merge by targeting an attacker-controlled branch ([`src/context/instruction-files.ts`](../../src/context/instruction-files.ts)). | On GitHub, trusted means OWNER, MEMBER or COLLABORATOR, the issue author, or a login passed with `--feedback-authors`. On Linear, comments from workspace members are trusted and comments posted by integrations are not. GitLab has no association model, so GitLab comments are trusted by default; set `--feedback-authors` there to make comment trust a boundary, and from then on comments from unlisted authors are ignored. A goal hijack is still contained by the sandbox and the delivery gates below. |
| ASI02 | Tool Misuse and Exploitation | The sandbox drops all Linux capabilities except three file-ownership ones, sets `no-new-privileges`, runs as a non-root user and caps memory, CPU and PIDs ([`src/sandbox/docker.ts`](../../src/sandbox/docker.ts), [`src/sandbox/limits.ts`](../../src/sandbox/limits.ts)). `--egress` limits outbound traffic to an allowlist and rejects look-alike hosts ([`src/sandbox/egress-allow.mjs`](../../src/sandbox/egress-allow.mjs)). Runs started from the Hub always use the LLM proxy and the egress enclave. | `--egress` is opt-in for CLI runs. Turn it on (or `--llm-proxy`, which implies it) wherever the sandbox should not reach arbitrary hosts. |
| ASI03 | Identity and Privilege Abuse | GitHub and GitLab tokens stay on the host and never enter the sandbox. With `--llm-proxy` the sandbox gets a per-run nonce while a sidecar holds the real model key ([`src/sandbox/llm-proxy.ts`](../../src/sandbox/llm-proxy.ts)). The Hub uses a per-launch token handed to the browser in the launch URL fragment ([`src/hub/server.ts`](../../src/hub/server.ts), [`src/hub/static.ts`](../../src/hub/static.ts)). The shadow approver runs as a separate job with an allowlisted set of `gh` calls. | A Linear run passes the Linear API key into the sandbox so the agent can read the issue. Subscription credentials for Codex (`CODEX_AUTH_JSON`) and Cursor keys are not proxied; see [boundaries.md](boundaries.md#host-llm-proxy). |
| ASI04 | Agentic Supply Chain Vulnerabilities | The sandbox, runner and hub base images are pinned by digest, the bundled CLIs by exact version, and the Cursor tarball by checksum ([`docker/`](../../docker/)). `.dockerignore` keeps `.env` files and local state out of image layers. `pnpm sbom` produces an image SBOM. Repository config under `.vanguard/` and skills under `.github/vanguard-skills/` are treated as trusted code, and reviewers load skills from the repository's default branch, not from the branch under review or the one it targets, so neither a PR nor the branch it targets can change the skills its own review uses ([skills.md](../skills.md)). | Pin the reusable workflows to a release tag (`@v1`) rather than `@main` if you want changes to reach your repo only on release. |
| ASI05 | Unexpected Code Execution (RCE) | Agent code runs only inside the sandbox. Copy-back drops CI config paths (`.github/workflows/`, `.github/actions/`, `.gitlab-ci.yml`, `.gitlab/**.yml`) so agent code cannot become CI code ([`workflowPaths()` in `src/core/vanguard.ts`](../../src/core/vanguard.ts)). Host git commands run with repository hooks disabled ([`src/worktree/host-git.ts`](../../src/worktree/host-git.ts)). The PR reviewer never checks out or runs PR code, and revise refuses PRs from forks. | Host git hardening is on `main` and ships in the next release (1.13.0); v1.12.0 does not include it. |
| ASI06 | Memory and Context Poisoning | Retrospective memory is a deterministic, redacted host-side digest and is passed to later runs as advisory context only ([`src/core/retrospective-memory.ts`](../../src/core/retrospective-memory.ts)). Run records are masked for secret patterns before they are stored ([`src/core/run-store.ts`](../../src/core/run-store.ts)). The approver reads its policy from the base branch only. | `.vanguard/` is gitignored operational state on the host, not committed source. |
| ASI07 | Insecure Inter-Agent Communication | Stages exchange data through the host, not through direct agent-to-agent channels. The LLM proxy and sidecars validate a per-run nonce. Review output follows a fixed verdict contract that the host parses ([`src/runners/pr-review.ts`](../../src/runners/pr-review.ts)). | Taskcell has no multi-agent message bus; this row covers the stage hand-offs and the proxy. |
| ASI08 | Cascading Failures | A per-run cost cap ($5 by default) stops a run that overspends ([`src/pipeline/pipeline.ts`](../../src/pipeline/pipeline.ts)). Repair loops stop after two rounds by default (`--max-repair-iterations`). `--max-turns` and `--max-budget-usd` are passed to the Claude Code CLI ([`src/agents/claude-code.ts`](../../src/agents/claude-code.ts)). `--max-tasks` caps how many issues one CI run claims. The approver has a kill switch. | The budget is a hard mid-stage stop on Claude-family providers and checked after each stage on others; see [cli.md](../cli.md#cost-and-limits). |
| ASI09 | Human-Agent Trust Exploitation | Every change ends as a pull request that a human reviews and merges. Taskcell never merges. The approver runs in shadow mode: it records a decision and never merges, approves or labels ([`src/approver/approve.ts`](../../src/approver/approve.ts)). A PR opens as a draft when a gate failed or no verify command ran, and the Proof of Work block hashes the verify output ([autonomous-loop.md](../autonomous-loop.md#proof-of-work)). | Treat the agent's PR description as a claim to check against the diff, not as evidence. |
| ASI10 | Rogue Agents | The whole design assumes the agent is hostile ([SECURITY.md](../../SECURITY.md)). Containment: sandbox, no repository token, opt-in egress allowlist and LLM proxy. Delivery gates on the host: CI config dropped on copy-back, an outgoing-diff secret scan that blocks the push ([`src/runners/deliver-change.ts`](../../src/runners/deliver-change.ts), [`src/core/secret-scan.ts`](../../src/core/secret-scan.ts)), and human review. | Each run leaves an audit trail under `.vanguard/runs/` (transcripts, diff, git bundle, metrics). |

## OWASP Top 10 for LLM Applications 2026

| ID | Risk | Taskcell controls | Notes |
|---|---|---|---|
| LLM01 | Prompt Injection | Same as ASI01: prompt-tag escaping, untrusted-content instructions in the reviewer, comment trust, workflow actor gates, default-branch-only instruction files for `review-pr`/`review-mr`. | Containment matters more than detection here: the controls under ASI02, ASI05 and ASI10 limit what an injected instruction can do. |
| LLM02 | Sensitive Information Disclosure | The outgoing diff is scanned for secret patterns and for the exact values of every credential injected into the run; a hit pushes nothing ([`src/runners/deliver-change.ts`](../../src/runners/deliver-change.ts)). Secrets reach the sandbox through an in-RAM tmpfs file, never argv or `docker inspect` ([`src/sandbox/docker.ts`](../../src/sandbox/docker.ts)). With `--llm-proxy` the model key never enters the sandbox. | Run records are also masked for secret patterns ([`src/core/run-store.ts`](../../src/core/run-store.ts)). |
| LLM03 | Excessive Agency | No repository token in the sandbox; the host does every push and PR. CI config is never copied back. Egress allowlist and LLM proxy. Shadow-only approver; humans merge. | The agent can edit files in its worktree and run commands in the sandbox. Everything it produces passes the host gates before it leaves. |
| LLM04 | Supply Chain | Same as ASI04. | |
| LLM05 | Data and Model Poisoning | Taskcell trains no models and keeps no training data. Persisted context (retrospective memory, metrics) is covered under ASI06. | Not applicable for training data. |
| LLM06 | Unbounded Consumption | Same as ASI08: run cost cap, turn cap, repair cap, `--max-tasks`, sandbox memory, CPU and PID limits. | Subscription providers bill plan usage, not tokens; `vanguard stats` reports cost per run and per model. |
| LLM07 | Misinformation | A deterministic triage gate rejects vague tickets before any model call. The conformance gate checks the diff against the spec ([`src/pipeline/conformance-gate.ts`](../../src/pipeline/conformance-gate.ts)). The host, not the agent, runs the verify command for Proof of Work. A second model reviews the diff in a fresh context. | A human still decides whether the change is correct. |
| LLM08 | Hidden Context Exposure | Prompts and skills are open source and hold no secrets. Credentials reach the agent by environment or file, never in prompt text. | Repository `CLAUDE.md` / `AGENTS.md` and skills are visible to anyone who can read the repo. |
| LLM09 | Vector and Embedding Weaknesses | Not applicable: Taskcell has no vector store or embedding retrieval. | |
| LLM10 | Improper Output Handling | Model output is treated as data. The host parses verdicts and markers with fixed contracts and strips review markers from untrusted text. Host subprocesses use argument arrays, not shell strings. The desktop app renders markdown without raw HTML. | |
